# 後台原生化與相容層（2026-10-23）

目前框架為 SvelteKit 3.1 / Svelte 5。院所日常工作頁已原生化，仍有既有管理與設定功能使用 React 19 / Radix 相容層，尚未全部移除 React。

## 原生 Svelte

`src/lib/components/admin/workspace/` 包含今日工作台、預約管理（清單、人員日曆、週行程）、客戶搜尋與代訂、可用時段及改期、狀態確認與回饋、叫號與報到、月曆與手機議程排班、休假及批次樣板／複製、客戶清單與再次預約入口。

這些日常工作流程不載入 React。瀏覽器回歸測試會檢查實際載入的 JS 資源，防止把 React 再帶回日常頁面。

## 仍使用相容層

- 平台管理員的總覽、院所列表、夥伴申請、使用者與系統設定、既有後台登入頁。
- 院所編輯（含 Logo 與完整營業設定）、人員／服務／公告設定、詳細客戶檔案與病史時間軸、營運分析／看診統計、訂閱管理與修改密碼。
- `LegacyAdminPage.svelte` + `runtime.tsx` 用於尚未移轉的整頁；`workspace/LegacyPanel.svelte` + `admin-compat/panels.ts` 只按需掛載個別設定與檔案。

## 共用邊界

`src/routes/admin/` 為 SvelteKit 路由、關閉 SSR。`AdminPage.svelte` 掛載前檢查角色及院所歸屬；後端仍獨立驗證所有授權與交易。

登入、token、主題維持同一份 Svelte 狀態。相容層沒有 Next.js 執行階段、依賴或另一份登入狀態。設定功能移轉時，須保留完整欄位、權限、API 與驗收案例；最後一頁移除後才能刪除 React / Radix 相依套件。

原生工作區的可用時段透過已授權 API 取得營業設定、班表、休假及預約快照；前端計算提供選擇介面，建立／改期最終仍由後端鎖定、檢查完整服務時段及衝突。沒有新增後端介面或資料庫遷移。
