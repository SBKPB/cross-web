# 首頁資訊與操作整理（2026-10-23）

## 設計目標

民眾進入首頁即可理解 Cross 提供看診、醫美諮詢與療程預約，直接搜尋或選擇服務類型。已預約的客戶能快速返回「我的預約」；院所另有清楚的導入與方案入口。

## 資訊層級

| 區域 | 調整後內容 | 操作目的 |
| --- | --- | --- |
| 首屏 | 「預約好時間，好好照顧自己」、兩句介紹、搜尋、四種服務類型 | 先找院所，再選服務與時段 |
| 搜尋下方 | 「已經有預約？」與「查看我的預約」 | 讓回訪者直接查看預約狀態 |
| 如何預約 | 找院所 → 選服務與時間 → 核對送出 | 用三段短句解釋流程，不重複大型卡片與按鈕 |
| 院所導入 | 三項核心能力、導入及方案入口 | 區分民眾與院所需求，取代六張功能卡及重複導入區塊 |

沿用既有品牌圖片、色彩與 shadcn-svelte／Luma 元件。首頁不新增評分、客戶數或未驗證的合作背書；可預約項目依各院所設定提供。

## 操作與無障礙

- 搜尋使用標準 GET 表單，可用 Enter 送出；空查詢可瀏覽全部院所。
- 四個分類帶入搜尋頁既有篩選參數，沒有另外建立第二套搜尋邏輯。
- 未登入者點「我的預約」後登入，保留返回會員頁的目的地。
- 手機首屏保留搜尋，主圖置於操作之後；主要操作點擊高度至少 44px。
- 單一主標題、可見搜尋標籤、具名區塊與分類導覽、鍵盤焦點，保留既有 SEO 及深色模式。
- 院所後台沒有改動；共用導覽僅在首頁擴大預約與會員入口的點擊區。

## 驗證

`tests/homepage.test.mjs` 覆蓋伺服器輸出、搜尋結果、四種分類、會員登入導向、院所／方案導向，以及 360／390／768／1440px 亮暗色版面。所有驗收 API 使用虛構資料，不寫入正式預約或會員資料。

發布前執行型別檢查、lint、正式建置、完整測試與 Snyk Code。Snyk 副本僅包含原始碼、package.json、tsconfig.json 及 Svelte 編譯衍生 JavaScript，不包含環境檔或憑證；發布證據與結果保存在上層 `docs/homepage-refresh-2026-10-23.md`。
